# Architecture Documentation

システム全体のアーキテクチャ設計と技術仕様を記録するディレクトリです。

## ディレクトリ構成

- `database-design.md`: データベース設計（PostgreSQL + Neo4j）
- その他のアーキテクチャドキュメントは必要に応じて追加

## アーキテクチャドキュメントの目的

### 1. 設計方針の統一
- 技術選択の理由と根拠を明文化
- チーム内での設計判断の共有
- 一貫した開発方針の維持

### 2. 長期的な保守性
- 将来の機能拡張時の指針
- 技術的負債の回避
- リファクタリング時の参考資料

### 3. 新メンバーへの知識移転
- システム全体の理解促進
- 既存設計の背景説明
- 開発効率の向上

## ドキュメント管理方針

### 更新タイミング
- 重要な技術選択を行った時
- アーキテクチャの変更を行った時
- 新しい技術を導入した時

### 内容の種類
- **設計原則**: システム全体の基本方針
- **技術選択**: 使用技術とその理由
- **制約事項**: 技術的・ビジネス的制約
- **今後の計画**: 拡張予定と技術改善計画

## 関連ドキュメント

- `development/`: 実装時の記録・証跡
- `design/`: UI/UXデザイン関連
- API仕様書: `redocly/openapi/`

## メンテナンス

アーキテクチャドキュメントは生きた文書として、システムの進化に合わせて継続的に更新してください。
