# プロジェクト基礎知識（全担当共通）

## 🎯 Odyssage プロジェクト概要

### プロジェクト名・ビジョン
**Odyssage（オデッサージュ）**: 非同期型TRPGプラットフォーム

**核心価値**: 「忙しくて対面でTRPGができない人でも、自分のペースで楽しめる体験を提供する」

### 解決する課題
- **時間制約**: 対面TRPG開催の困難（スケジュール調整・時間確保）
- **継続性**: セッション中断・キャンペーン継続の困難
- **記録**: プレイ体験の記録・振り返りの困難

### 提供価値
- **非同期プレイ**: 各プレイヤーが自分のペースで進行
- **自動記録**: プレイ体験が物語として自然に記録
- **個別体験**: プレイヤーごとの選択・反応による個性的な物語展開

## 👥 3つのユーザー文脈（Context-First Architecture）

### 重要発見（Sprint 3成果）
バックエンドAPI実装過程で、3つの独立したユーザー文脈が明確化

#### 🎭 Author（シナリオ作成者）文脈
**役割**: TRPGシナリオの創作・公開
- **価値体験**: 自分の創作物を多くのプレイヤーに楽しんでもらう
- **主要機能**: シナリオ作成・編集・公開設定・利用状況確認
- **API範囲**: `/api/authors/{uid}/scenarios/`

#### 🎲 GM（ゲームマスター）文脈  
**役割**: セッション運営・プレイヤー管理
- **価値体験**: プレイヤーと共に物語を紡ぐ体験
- **主要機能**: セッション作成・プレイヤー招待・進行管理・ファシリテーション
- **API範囲**: `/api/gms/{uid}/sessions/`

#### ⚔️ Player（プレイヤー）文脈
**役割**: 非同期TRPGプレイの主体験
- **価値体験**: 自分のペースで楽しむ物語体験
- **主要機能**: シナリオ探索・セッション参加・非同期プレイ・プレイログ閲覧
- **API範囲**: `/api/players/{uid}/`

### 文脈間関係
```
Author → シナリオ作成 → GM → セッション運営 → Player → 体験・記録
   ↑                                            ↓
   └─── フィードバック・利用状況 ←←←←←←←←←←←←←←────┘
```

### 設計への影響
- **独立性**: 各文脈は独立した価値を提供
- **専用設計**: 文脈ごとの専用API・UI・機能セット
- **段階的実装**: Player→GM→Author順の価値中心実装

## 🏗️ アーキテクチャ原則

### Context-First Architecture
**原則**: ユーザー文脈を第一に考えた設計

1. **文脈独立性**: 各文脈が独立して価値を提供
2. **専用最適化**: 文脈ごとの最適なAPI・UI設計
3. **価値中心**: 技術ではなくユーザー価値を中心とした実装

### Feature-Sliced Design (FSD)
**原則**: レイヤー・スライス・セグメントによる構造化

```
apps/frontend/src/
├── app/           # アプリケーション設定・ルーティング
├── pages/         # 画面単位
├── widgets/       # 画面パーツ
├── features/      # ビジネス機能
├── entities/      # ドメインエンティティ
└── shared/        # 共通コンポーネント・ユーティリティ
```

### 統合アプローチ
Context-First（文脈中心） + FSD（技術構造）の統合

- **React + Next.js**: UIライブラリ・フレームワーク
- **TypeScript**: 型安全性確保
- **スタイリング**: 未定（プロジェクト進行で決定）

### バックエンド（将来統合）

### データベース（将来統合）

## 📋 品質基準

### 必須品質要件
- **TypeScript**: 型安全性100%（`any`禁止）
- **ESLint**: エラー0件（警告最小化）
- **テスト**: 重要機能の適切なテストカバレッジ
- **ビルド**: エラーなし・警告最小化

### パフォーマンス目標
- **API応答時間**: 平均500ms以内
- **フロントエンド初期表示**: 3秒以内
- **バンドルサイズ**: 圧縮後1MB以内

### コード品質指標
- **関数複雑度**: 7以下（ESLint制限）
- **ファイルサイズ**: 適切な分割・責任分担
- **import順序**: ESLint自動整理

## 🎯 現在の状況（Sprint 4）

### 方針：⚔️ Player文脈フロントエンドMVP
- **バックエンド除外**: MVPからバックエンドを完全除外
- **フロントエンド集中**: モックデータによる価値体験検証
- **Player文脈限定**: Author・GM文脈は除外

### 技術的対応
- **データ**: JSONモックデータ + ローカルストレージ
- **API**: モック関数・フェイクAPI実装  
- **状態管理**: クライアント完結の状態管理

### 目標体験
「シナリオを探してプレイ開始」までの完全体験

1. シナリオ探索・検索
2. シナリオ選択・詳細確認
3. セッション参加・プレイ開始
