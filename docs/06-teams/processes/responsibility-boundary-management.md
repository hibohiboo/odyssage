# 責務分界管理指針

## 📋 目的・重要性

### **責務分界管理の必要性**
複数Claude Code体制では、各担当者の専門性を最大限活用するために、明確な責務分界の確立・維持が重要です。

```markdown
重要な理由:
✅ 専門性活用: 各担当者の専門領域・判断権限の最大限活用
✅ 効率化: 重複作業・無駄な調整の防止
✅ 品質向上: 専門知識・経験による高品質成果物
✅ 自律性確保: 創造性・判断力・責任感の発揮環境
```

### **越境問題のリスク**
```markdown
越境による問題:
❌ 専門性の阻害: 技術判断・実装方法への不適切な介入
❌ 効率低下: 責任の曖昧化・重複作業・調整コスト増大
❌ 品質低下: 専門知識不足による不適切な判断・実装
❌ モチベーション低下: 自律性の侵害・創造性の阻害
```

## 🎯 **各役割の責務分界定義**

### **設計担当の適切な責務**

#### **✅ 設計専門領域**
```markdown
アーキテクチャ設計:
- システム全体構造・レイヤー設計・依存関係設計
- データ設計・ドメインモデル・永続化戦略
- 画面構成・UX設計・ユーザーフロー設計

制約・要件管理:
- MVP制約適用・機能範囲明確化・段階的実装方針
- 品質要件・パフォーマンス要件・技術制約定義
- ビジネス要件・ユーザー要件の技術要件への変換

設計文書管理:
- 設計決定の文書化・体系化・継続的更新
- アーキテクチャ整合性・一貫性の継続確保
- 設計知識・判断理由・代替案検討の記録
```

#### **❌ 実装担当の専門領域（越境禁止）**
```markdown
技術実装詳細:
- React Hook使用方法・TypeScript実装パターン
- 具体的コード記述・実装手順・技術選択
- パフォーマンス最適化・メモリ管理・実行効率

実装方法判断:
- ライブラリ選択・フレームワーク活用方法
- コードアーキテクチャ・モジュール分割・命名規則
- テスト実装・デバッグ方法・品質確認手順

作業管理・スケジューリング:
- 実装時間見積もり・作業順序・効率化手法
- 技術調査・学習・実装試行の方法・時間配分
```

### **実装担当の適切な責務**

#### **✅ 実装専門領域**
```markdown
技術実装:
- コード実装・技術選択・実装パターン選択
- ライブラリ活用・フレームワーク統合・API活用
- パフォーマンス最適化・メモリ効率・実行効率

品質確保:
- 単体テスト・統合テスト・実装品質確認
- ESLint・TypeScript・コード品質基準適用
- リファクタリング・技術負債解決・保守性向上

実装プロセス:
- 実装手順・作業効率化・技術調査・学習
- 実装時間管理・進捗調整・技術課題解決
```

#### **❌ 設計担当・他担当の専門領域（越境禁止）**
```markdown
設計判断:
- アーキテクチャ決定・設計方針・全体構造
- ビジネス要件解釈・MVP制約適用・機能範囲
- UX設計・画面設計・ユーザーフロー

プロジェクト管理:
- 全体スケジュール・優先度・リソース配分
- チーム調整・意思決定・方針変更
```

### **リーダーの調整責務**

#### **✅ リーダー専門領域**
```markdown
責務分界管理:
- 責務分界の監視・維持・調整・改善
- 越境問題の早期発見・予防・解決
- 各担当者の専門性活用・自律性確保

協働促進:
- チーム間連携・情報共有・意思決定支援
- 課題解決・合意形成・コンフリクト調整
- プロジェクト進行・品質確保・目標達成

プロセス改善:
- 協働プロセス・情報共有・品質保証の改善
- 学習・知見蓄積・継続的改善の促進
```

## 🚨 **越境問題の発見・対応**

### **越境パターンの識別**

#### **設計担当の越境パターン**
```markdown
実装詳細への介入:
❌ React Hook使用法・TypeScript記述の具体指示
❌ コード例・実装パターンの詳細記述
❌ 実装手順・作業時間・技術調査の指定

例（問題のある記述）:
「useParams<{ sessionId: string }>()を使用して...」
「30分で実装完了予定...」
「try-catch文で以下のように...」
```

#### **実装担当の越境パターン**
```markdown
設計判断への介入:
❌ アーキテクチャ方針・設計原則の変更要求
❌ MVP制約・機能範囲の独断変更
❌ UX設計・画面設計の変更実装

例（問題のある行動）:
「設計にない機能を追加実装」
「MVP範囲外の機能を実装」
「設計意図と異なるUX変更」
```

### **早期発見・予防方法**

#### **定期的チェック**
```markdown
日次確認:
✅ 各担当者の作業内容・責務分界の確認
✅ 作成文書・成果物の責務適合性確認
✅ 協働・相談内容の適切性確認

週次評価:
✅ 責務分界・専門性活用の効果評価
✅ 越境問題・協働課題の分析・改善
✅ プロセス・ルールの効果確認・調整
```

#### **予防的対策**
```markdown
作業開始時:
✅ 責務分界・期待成果物の明確確認
✅ 協働方法・相談範囲の事前合意
✅ 越境リスク・注意事項の共有

作業中:
✅ 定期的な責務確認・調整・相談
✅ 疑問・判断迷い時の適切なエスカレーション
```

### **発見時の対応手順**

#### **即座対応（越境発見時）**
```markdown
1. 問題特定（5分）:
- 越境の具体的内容・影響範囲の確認
- 意図・背景・原因の理解
- 緊急度・対応要求の評価

2. 調整対応（15分）:
- 当事者への丁寧な説明・調整依頼
- 適切な責務分界・協働方法の確認
- 修正・改善の具体的方法・期限

3. 予防改善（30分）:
- 同様問題の予防策・ルール明確化
- プロセス・チェック方法の改善
- 学習・共有・継続的改善
```

#### **根本的改善（週次）**
```markdown
原因分析:
- 越境の根本原因・システム的要因
- プロセス・ルール・コミュニケーションの改善要求
- 教育・理解・習慣の改善必要性

体制改善:
- 責務分界ルール・プロセスの見直し・強化
- チェック方法・予防策の改善・標準化
- 教育・オンボーディング・継続学習の改善
```

## 🤝 **効果的協働の実現**

### **専門性尊重の協働**

#### **設計 ↔ 実装協働**
```markdown
✅ 適切な協働:
設計担当 → 実装担当:
- 設計仕様・制約・意図の明確な説明
- 技術相談・疑問解決・設計調整の支援
- 品質基準・アーキテクチャ整合性の確認

実装担当 → 設計担当:
- 設計仕様の理解確認・疑問・課題の相談
- 技術制約・実装困難・代替案の提案
- 実装結果・品質・設計適合性の報告

❌ 避けるべき越境:
- 設計担当による実装方法・コード記述の指定
- 実装担当による設計判断・アーキテクチャ変更
```

#### **相談・支援の適切な範囲**
```markdown
設計担当の技術支援:
✅ 設計意図・制約・要件の解説・相談対応
✅ アーキテクチャ整合性・品質基準の確認
✅ 代替案検討・トレードオフ・判断材料の提供

❌ 技術実装への過度な介入:
- 具体的コード記述・実装パターンの指定
- 実装時間・作業手順・効率化方法の指示
- 技術選択・ライブラリ活用方法の詳細指定
```

### **建設的なフィードバック**

#### **適切なフィードバック方法**
```markdown
専門性を活かしたフィードバック:
✅ 各専門領域の観点からの建設的提案
✅ 品質向上・効率改善・価値向上への貢献
✅ 相手の専門性・判断・自律性の尊重

具体例:
設計担当 → 実装担当:
「この実装は設計意図と整合していますが、将来の拡張性を考慮すると...という観点もあります。実装方法は技術的にお任せしますが、ご検討いただけますでしょうか。」

実装担当 → 設計担当:
「設計仕様を実装する中で、...という技術制約があることが分かりました。設計の意図を保ちつつ、...という代替案をご検討いただけますでしょうか。」
```

実践からの学習:

改善サイクル:

柔軟な調整:
✅ プロジェクト特性・チーム特性に応じた調整
✅ 新しい課題・要求に対する適応・進化
✅ より効果的な方法・プロセスの探求・試行

✅ 改善・調整の効果的方法・タイミング

## 📝 **実践ガイドライン**

### **新規参加時の責務分界確立**

#### **オンボーディング時**
```markdown
1. 役割・責務の明確化（30分）:
- 専門領域・責任範囲・期待成果の確認
- 他担当との責務分界・協働方法の理解
- 越境回避・適切な相談・支援要請の方法

2. 実践的確認（1時間）:
- 具体的作業・成果物での責務確認
- 疑問・判断迷い時の相談・エスカレーション方法
- 効果的協働・専門性活用の方法・期待

3. 継続的調整（毎日5分）:
- 責務分界・協働状況の定期確認
- 問題・改善要求の早期発見・対応
```

### **プロジェクト進行中の管理**

#### **日常的な責務分界管理**
```markdown
作業開始時:
✅ 本日作業・責務範囲・協働予定の確認
✅ 疑問・相談事項・エスカレーション要求の整理

作業中:
✅ 責務分界を意識した作業・成果物作成
✅ 疑問・判断迷い時の適切な相談・支援要請

作業完了時:
✅ 責務適合性・協働効果の評価・記録
✅ 改善提案・学習事項の共有・蓄積
```

**責務分界管理の成功に向けて**

明確な責務分界の確立・維持により、各担当者の専門性を最大限活用し、効率的で高品質な協働を実現します。

継続的な学習・改善により、より効果的な責務分界・協働方法を追求し、プロジェクト成功・チーム成長・価値創出を実現していきましょう。
