# プレイヤー選択肢提案機能要件書（将来機能）

## 📅 文書概要

**作成日**: 2025-08-16  
**ステータス**: 将来機能（MVP範囲外）  
**対象**: Player文脈での拡張機能  
**実装時期**: MVP完了後の Phase 2以降  

## 🎯 機能概要

### 核心価値
**「プレイヤーがGMに対してシーン内で新しい選択肢を提案し、承認されることで物語に創造的に参加できる」**

### TRPG的背景
従来のTRPGでは、プレイヤーはGMが用意した選択肢以外にも自由に行動を宣言でき、GMがそれを判定して物語に反映する。この機能は、デジタルTRPGでその体験を実現することを目指す。

## 🔧 機能要件

### 基本フロー
1. **提案フェーズ**: プレイヤーがシーン内で「その他の行動」を選択
2. **記述フェーズ**: フリーテキストで行動内容を記述
3. **承認フェーズ**: GMに通知が送られ、承認・却下・修正提案を判断
4. **反映フェーズ**: 承認された場合、新しい選択肢として追加または専用シーンへ遷移

### 詳細機能要件

#### 1. プレイヤー側機能
```markdown
**提案入力**:
- フリーテキストでの行動提案
- 行動の意図・期待する結果の記述
- 提案の緊急度設定（通常/重要）

**提案管理**:
- 提案履歴の確認
- 提案ステータスの追跡
- GMからのフィードバック確認
```

#### 2. GM側機能
```markdown
**提案レビュー**:
- 提案の詳細確認
- セッション・シーン文脈での適切性判断
- 他プレイヤーへの影響度評価

**回答アクション**:
- 承認（そのまま実行）
- 修正承認（条件付きで実行）
- 却下（理由付きで拒否）
- 保留（後で判断）
```

#### 3. システム機能
```markdown
**通知システム**:
- GMへのリアルタイム通知
- プレイヤーへの回答通知
- 他参加者への状況共有

**履歴管理**:
- 提案・回答の記録
- セッション終了後の振り返り用データ
- 承認率等の統計情報
```

## 📊 データ構造設計

### 提案データ構造
```typescript
interface CustomChoiceProposal {
  // 基本情報
  id: string;
  sessionId: string;
  sceneId: string;
  playerId: string;
  
  // 提案内容
  proposedAction: string; // プレイヤーの提案テキスト
  actionDescription?: string; // 詳細説明
  expectedOutcome?: string; // 期待する結果
  
  // 提案メタデータ
  priority: 'normal' | 'important'; // 緊急度
  category: 'action' | 'dialogue' | 'creative' | 'other'; // 提案カテゴリ
  
  // ステータス管理
  status: ProposalStatus;
  
  // GM回答
  gmResponse?: GMResponse;
  
  // システム情報
  createdAt: string; // ISO date
  updatedAt: string; // ISO date
  resolvedAt?: string; // 解決日時
}

type ProposalStatus = 
  | 'pending'    // 承認待ち
  | 'approved'   // 承認済み
  | 'modified'   // 修正承認
  | 'rejected'   // 却下
  | 'expired';   // 期限切れ

interface GMResponse {
  responseType: 'approve' | 'modify' | 'reject' | 'defer';
  feedback?: string; // GMからのコメント
  
  // 修正承認の場合
  modifiedAction?: string;
  modifiedDescription?: string;
  
  // 承認時の遷移先
  customSceneId?: string; // 専用シーン作成の場合
  nextSceneId?: string; // 既存シーンへの遷移
  
  // システム情報
  respondedAt: string; // ISO date
  gmId: string;
  gmName: string;
}
```

### セッション状態への統合

interface Session {

## 🎮 ユーザー体験設計

### プレイヤー体験
```markdown
## 提案時の体験
1. シーン内で「その他の行動を提案」ボタンが表示
2. モーダルで提案内容を入力（テキストエリア + 説明）
3. 提案送信後、「GM承認待ち」状態を表示
4. 他の行動も継続可能（提案は非同期処理）

## 回答受信時の体験  
5. GMから回答があると通知で知らせ
6. 承認の場合、新しい選択肢として追加表示
7. 却下の場合、理由とともに通知
8. 修正承認の場合、修正内容を確認後実行可能
```

### GM体験
```markdown
## 提案確認の体験
1. プレイヤーから提案があると即座に通知
2. セッション進行中の専用パネルで提案一覧確認
3. 各提案に対して承認・却下・修正をワンクリック選択
4. 必要に応じてプレイヤーへフィードバックコメント

## セッション管理の体験
5. 提案機能の有効/無効をセッション毎に設定
6. 提案履歴をセッション終了後に確認・分析
7. 頻繁に創造的提案をするプレイヤーの把握
```

## 🔗 既存機能との連携

### Scene・Event システムとの統合
```markdown
**Event拡張での実現**:
- 新しい EventType として 'custom_proposal' を追加
- GM承認後、動的に ChoiceEventData を生成
- 専用シーン作成の場合、動的に Scene を生成

**データフロー**:
1. 提案 → CustomChoiceProposal として保存
2. GM承認 → Event または Scene の動的生成
3. プレイヤー実行 → 通常の選択フローで処理
```

### セッション管理との統合
```markdown
**GMインターフェース拡張**:
- セッション管理画面に提案レビューパネルを追加
- リアルタイム通知システムとの連携
- セッション設定での提案機能制御

**参加者体験への影響**:
- 他プレイヤーにも承認された提案を共有
- セッション活性度の向上
- より創造的なプレイ体験の提供
```
