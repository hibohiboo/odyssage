## 📋 基本情報

**作成者**: リーダー

**適用範囲**: Sprint 4以降の継続的ドキュメント管理

## 🎯 ドキュメント分類・管理方針

### 分類基準
- **Sprint固有文書**: 特定Sprintに関連・一時的性格
- **生きた文書**: チーム運営・継続的更新・長期活用

## 📁 Sprint固有文書（一時的・記録性）

### 配置場所
```
docs/03-development/sprints/sprint_XXX/
├── collaboration/           # Sprint内協働記録
├── reviews/                # Sprint内レビュー記録  
├── planning/               # Sprint計画・戦略
└── completion/             # Sprint完了・振り返り
```

### Sprint固有文書の性格
- **記録性**: Sprint活動・決定・経緯の記録
- **一時性**: 当該Sprint完了後は参照頻度低下
- **協働性**: Sprint内チーム協働・コミュニケーション
- **学習性**: 将来Sprint・チーム活動への学習材料

### Sprint固有文書例
- POレビューフィードバック反映記録
- 設計担当・実装担当・テスト担当間の作業指示・報告
- Sprint内の課題・解決・調整記録
- 実装フェーズ準備・開始通知
- チーム協働・コミュニケーション記録

## 📚 生きた文書（継続的・運用性）

### 配置場所・分類
```
docs/06-teams/              # チーム運営・役割・プロセス
├── roles/                  # 役割定義・責任範囲
├── processes/              # プロセス・手順・基準
└── guidelines/             # 運営指針・品質基準

docs/02-architecture/       # 技術・設計文書
├── player-context/         # Player文脈設計
├── shared/                 # 共通技術・設計
└── data/                   # データ設計・構造

docs/01-project/            # プロジェクト基盤文書
├── overview/               # プロジェクト概要・方針
├── requirements/           # 全体要件・制約
└── standards/              # 品質基準・開発標準
```

### 生きた文書の性格
- **継続性**: 複数Sprint・長期間にわたる活用
- **進化性**: 継続的更新・改善・拡張
- **参照性**: 日常業務・意思決定での頻繁な参照
- **標準性**: チーム運営・技術選択の基準・指針

### 生きた文書例
- **役割定義**: implementation-specialist.md・test-specialist.md・design-specialist.md
- **プロセス**: test-responsibility-boundaries.md・quality-assurance-process.md
- **技術設計**: requirements.md・architecture.md・data-design.md
- **品質基準**: mvp-guidelines.md・coding-standards.md

## 🔄 文書ライフサイクル管理

### Sprint固有文書のライフサイクル
1. **作成**: Sprint活動・協働に基づく作成
2. **活用**: Sprint内での参照・更新・協働活用
3. **保存**: Sprint完了時の記録として保存
4. **学習**: 将来Sprint・チーム改善への学習材料

### 生きた文書のライフサイクル
1. **初期作成**: チーム活動・プロジェクト要件に基づく作成
2. **継続更新**: 実践・学習・改善に基づく継続的更新
3. **版管理**: 重要変更時の履歴・理由記録
4. **品質維持**: 定期的品質確認・整合性確保

## 📊 文書品質・整合性管理

### Sprint固有文書品質基準
- **記録正確性**: Sprint活動・決定・経緯の正確な記録
- **協働効率**: チーム協働・コミュニケーション効率化
- **学習価値**: 将来活動・改善への学習価値確保

### 生きた文書品質基準
- **現在性**: 最新状況・実践内容との整合性
- **完全性**: 必要情報・手順・基準の網羅性
- **一貫性**: 他文書・プロジェクト全体との整合性
- **実用性**: 日常業務・意思決定での実用的価値

## 🚨 管理上の注意事項

### 文書分類の徹底
- **適切な配置**: 文書性格に基づく適切なディレクトリ配置
- **明確な分類**: Sprint固有・生きた文書の明確な分類
- **整合性確保**: 文書間の参照・依存関係の適切な管理

### 重複・冗長の回避
- **役割文書**: 06-teams/roles/ に集約・重複回避
- **技術文書**: 02-architecture/ に集約・一元管理
- **プロセス文書**: 06-teams/processes/ に集約・標準化

### 更新・保守責任
- **生きた文書**: 関連チーム・役割による継続的更新責任
- **Sprint文書**: 作成者・関連メンバーによる品質・正確性責任
- **整合性確認**: 定期的な文書間整合性・品質確認

## 💡 効率的ドキュメント活用

### 参照効率化
- **明確な構造**: 目的・内容に基づく迅速な文書発見
- **適切な粒度**: 過度に詳細・過度に抽象的な内容の回避
- **実用的内容**: 日常業務・意思決定での実際的価値

### 協働効率化
- **Sprint内協働**: Sprint固有文書による効率的な協働・記録
- **継続的活用**: 生きた文書による安定的な運営・品質確保
- **学習・改善**: 両文書の連携による継続的学習・改善

---

**ドキュメント管理の重要性**:

適切なドキュメント分類・管理により、Sprint活動の効率化と継続的なチーム運営・品質向上を実現します。

Sprint固有の協働記録と、継続的なチーム運営基盤の両立により、効率的で高品質なプロジェクト推進を目指します。
