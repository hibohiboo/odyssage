# Player文脈MVP設計概要

## 📋 設計スコープ

### 対象範囲
- **文脈**: ⚔️ Player文脈のみ
- **MVP範囲**: 「セッション探索 → 参加 → プレイ開始」体験
- **技術制約**: バックエンド除外（モックデータ・フロントエンド単体）

### 除外範囲
- 🎭 Author文脈（シナリオ作成・編集）
- 🎲 GM文脈（セッション運営・管理）
- バックエンドAPI・データベース連携

## 🎯 ユーザー価値・体験設計

### 核心価値
**「開催中のTRPGセッションに気軽に参加してプレイ体験を開始できる」**

### ユーザーフロー（大まか）
1. **セッション探索**: 開催中・参加可能なTRPGセッションを閲覧・発見
2. **セッション参加**: セッション詳細（シナリオ情報含む）確認・参加判断
3. **プレイ開始**: 非同期TRPG体験の開始・継続

### 体験品質目標
- **発見の楽しさ**: 参加可能な魅力的なセッションとの出会い
- **参加の安心感**: セッション・シナリオ詳細情報に基づく参加判断
- **継続の満足感**: 参加中セッションの進行状況把握・継続プレイ

## 📱 画面構成（基本）

### 必須画面（3画面）
1. **セッション一覧画面**: 開催中セッションの探索・参加状況確認
2. **セッション参加画面**: セッション詳細・シナリオ情報・参加手続き
3. **プレイ画面**: 非同期プレイの基本体験

### 画面間遷移（概要）
```
セッション一覧 → セッション参加 → プレイ画面
     ↑              ↓            ↓
    戻る・他探索    戻る・他探索    継続・履歴
     ↑                            ↓
   参加中表示 ←←←←←←←←←←←←←←←←   セッション一覧に戻る
```

## 🏗️ アーキテクチャ方針

### 基本構造
- **Context-First**: Player文脈専用の設計・実装
- **FSD統合**: Feature-Sliced Design原則の適用
- **モック駆動**: バックエンド非依存の状態管理

### 主要技術選択
- **状態管理**: Redux Toolkit（グローバル）+ SWR（データ）+ useState（UI）
- **スタイリング**: Tailwind CSS + 既存UIライブラリ
- **データ**: JSONモックデータ + LocalStorage

## 📊 データ構造（概要）

### 主要エンティティ
- **Scenario**: シナリオ情報（タイトル・概要・設定・難易度）
- **Session**: セッション情報（参加者・進行状況・開始時刻）
- **PlayState**: プレイ状態（選択履歴・現在位置・プレイヤー状態）

### モックデータ方針
- **リアルさ**: 実際のTRPG体験を模擬する内容
- **多様性**: 複数ジャンル・難易度のシナリオ
- **進行感**: セッション進行・他プレイヤーとの協調表現

## 🔄 状態管理方針

### 状態の分類
- **アプリ状態**: 認証・設定・ナビゲーション
- **セッション状態**: セッション一覧・詳細・参加状況
- **プレイ状態**: 参加中セッション・プレイ進行・選択履歴
- **UI状態**: モーダル・ローディング・フォーム

### 永続化方針
- **LocalStorage**: セッション参加状況・プレイ進行
- **SessionStorage**: 一時的なUI状態
- **メモリ**: リアルタイムUI状態

## 🚀 実装方針

### Phase 1対象（設計のみ）
- アーキテクチャ詳細設計
- UI/UX詳細設計
- モックデータ構造設計

### 実装境界
- **設計担当**: 要求・画面・データ構造の設計
- **実装担当**: コンポーネント・状態管理・ロジックの実装
- **明確な分離**: 設計は実装詳細に立ち入らない

## 🎯 成功基準

### 設計品質
- **理解しやすさ**: 開発者が容易に理解できる設計
- **実装可能性**: 技術的制約内での実現可能性
- **拡張性**: 将来のGM・Author文脈追加への対応

### ユーザー価値
- **体験の完結性**: MVP範囲でのTRPG価値実感
- **操作の直感性**: 迷わない画面遷移・操作フロー
- **情報の十分性**: 判断に必要な情報の適切な提示
