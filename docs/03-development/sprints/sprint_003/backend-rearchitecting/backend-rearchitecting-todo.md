### 📊 課題特定・優先度評価

#### **✅ APIパス構造設計（完了: 2025-08-11）**

- [x] **ユーザーロール定義・統一**
  - [x] 3ロール統一: `authors` | `game-masters` | `players`  
  - [x] 英語・日本語対応表・権限マトリクス作成
  - [x] 各ロールの責務・機能範囲明確化
  - [x] **決定**: `game-masters`（明確性重視・一貫性確保）

- [x] **エンドポイント設計方針決定**
  - [x] **ハイブリッド方式**: 状態変更（RESTful） + ビジネスアクション（文脈特化）
  - [x] **基本構造**: `/api/{role}/{uid}/{resource}[/{id}][/actions/{action}]`
  - [x] **判定基準**: 単純属性変更 vs 複雑ビジネスロジック
  - [x] 既存実装（`/api/gm/{uid}/sessions/{id}`）との整合性考慮

- [x] **段階的移行戦略策定**
  - [x] **3フェーズ移行**: 新パス追加 → フロントエンド移行 → 旧API廃止
  - [x] **移行期間**: 8週間（2週間バックエンド + 4週間移行 + 2週間クリーンアップ）
  - [x] **リスク軽減**: 機能フラグ・監視・ロールバック準備
  - [x] **互換性保証**: 新旧API並行運用・段階的切り替え

- [x] **既存実装整合性課題特定**
  - [x] **パラメータ不整合**: `gm_id` → `uid` 統一必要
  - [x] **ロール表記揺れ**: `gm` → `game-masters` 統一必要  
  - [x] **OpenAPI仕様**: 統一後構造への準拠が必要
  - [x] **移行マッピング**: 既存5エンドポイント → 新構造への対応表作成
