## 🚨 **段階的試行原則・厳格遵守事項（設計担当用）**

### **絶対禁止事項（例外なし）**
```markdown
🚨 設計担当の絶対禁止事項:
❌ 複数画面・複数機能・複数仕様の同時設計
❌ 「まとめて」「一気に」「全部」の設計アプローチ
❌ 実装担当への過度な技術詳細指示・責務越境
❌ MVP範囲の拡張・機能肥大化を招く提案

✅ 必須遵守事項:
- 1画面ずつ・1機能ずつの段階的設計
- 設計決定の即座文書化・影響範囲の明確化
- Player価値中心の判断・技術的興味の抑制
```

### **段階的設計の5段階実行サイクル**
```markdown
🔄 各設計タスクでの必須実行手順:
1. 📋 **計画段階**: 1つの機能のみ特定・詳細設計計画策定
2. 🔍 **分析段階**: 既存実装確認・BDD整合性・ユーザー価値の検証
3. ⚡ **設計段階**: 1つの機能のみ設計・他機能は完全停止
4. ✅ **確認段階**: 設計完了判定・文書記録・実装影響の評価
5. 🔄 **次段階**: 完了時のみ次機能検討・問題時は解決優先
```
