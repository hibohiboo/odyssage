## 🎯 **乖離による影響・問題点**

### **1. BDD実行への影響**
- **依存**: BDDテストがバックエンドAPI・データベース環境に完全依存
- **複雑性**: MVP想定を超えた環境準備が必要
- **リスク**: API障害時のテスト実行不能

### **2. MVP戦略からの逸脱**
- **設計意図**: シンプルなモック・スタティックデータ表示
- **実装現実**: フル機能API連携実装
- **段階性**: MVP→本格実装の段階性が失われている

### **3. 開発・保守の複雑化**
- **依存関係**: フロントエンドのバックエンド完全依存
- **テスト環境**: 複雑なテストデータ準備が必要
- **デバッグ**: API・DB問題の切り分けが困難

## 📋 **対応方針・選択肢**

### **選択肢1: モック実装への戻し**
```markdown
✅ 利点:
- 設計書との整合性確保
- BDDテストの単純化・高速化
- フロントエンド独立開発

❌ 欠点:
- 既存実装の大幅改修が必要
- API統合の追加開発が将来必要
```

### **選択肢2: 設計書の更新・現実追認**
```markdown  
✅ 利点:
- 実装済みコードの保持

❌ 欠点:
- MVP戦略の破綻
- BDD実行の複雑性継続
- 設計プロセスの信頼性低下
```

### **🎯 推奨方針: 選択肢2（設計書更新・現実追認）**
**理由**: 実装済みの品質・機能を活かし、BDD環境整備に集中
