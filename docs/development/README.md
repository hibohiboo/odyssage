# Development Documentation

このディレクトリには、開発時の設計判断や実装記録を保存します。

## ディレクトリ構成

- `development/`: 各機能の実装計画書・進捗記録
- その他のドキュメントは適宜追加予定

## ドキュメント作成指針

### 1. 実装計画書の作成ルール

各機能実装時は以下の構成でドキュメントを作成してください：

#### 必須セクション
- **プロジェクト概要**: 何を実装するかの明確な定義
- **アーキテクチャ分析**: 既存システムの理解
- **データモデル設計**: 必要なデータ構造の定義
- **実装計画**: 具体的なTODOリスト
- **実装ガイドライン**: 開発時の注意点・方針
- **進捗記録**: 日付別の作業履歴

#### 命名規則
- ファイル名: `{機能名}-{目的}.md`
- 例: `scenario-graphdb-implementation.md`

### 2. 設計判断の記録

重要な技術選択や設計判断は必ず以下を記録してください：

- **判断内容**: 何を選択したか
- **理由**: なぜその選択をしたか
- **代替案**: 他にどんな選択肢があったか
- **影響**: その判断による影響範囲

### 3. 進捗記録の更新ルール

- 日付別にセクションを作成
- 完了したタスクと次回予定を明記
- 問題や課題があれば詳細を記録
- 実装中に発見した新しい要件や制約を追記

### 4. TODOリストの管理

- `- [ ]` 未完了タスク
- `- [x]` 完了タスク
- 階層化でサブタスクを表現
- 担当者や期限が必要な場合は明記

## 参考例

詳細な書き方は `scenario-graphdb-implementation.md` を参考にしてください。

## メンテナンス

- 実装完了後も設計判断の参考として保持
- 将来の機能拡張時の参考資料として活用
- 定期的にリンク切れや情報の陳腐化をチェック
