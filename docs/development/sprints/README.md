# Sprints 運用ルール

## 基本方針

### Sprint運用の目的
- **継続的改善**: 1週間単位での迅速な改善サイクル
- **透明性確保**: 進捗と課題の可視化
- **知識蓄積**: 実装記録による学習・ナレッジ共有
- **品質向上**: 定期的な振り返りによる品質向上

### 運用原則
- **1週間スプリント**: 毎週金曜日開始、翌週木曜日終了
- **証跡重視**: すべての判断と実装過程を文書化
- **継続的学習**: レトロスペクティブでの改善点抽出
- **実用性重視**: 形式より実質的な価値創出を優先

## スプリント構成

### ディレクトリ構造
```
docs/development/sprints/
├── README.md                    # 運用ルール（本ファイル）
├── sprint_template/             # スプリントテンプレート
│   ├── SPRINT_CONFIG.md
│   ├── implementation.md
│   └── retrospective.md
├── sprint_001/                  # 過去スプリント（アーカイブ）
├── sprint_002/
├── sprint_003/                  # 現在スプリント
└── upcoming/                    # 次回予定
    └── backlog.md
```

### 必須ファイル構成
各スプリントディレクトリには以下ファイルを配置：

1. **SPRINT_CONFIG.md**: スプリント設定・目標・スケジュール
2. **[feature-name]-implementation.md**: 機能実装記録
3. **retrospective.md**: スプリント終了時の振り返り

## スプリント実行プロセス

### 金曜日: スプリント開始
1. **前スプリント完了確認**
   - [ ] レトロスペクティブ実施・記録
   - [ ] 完了項目の最終チェック
   - [ ] 未完了項目の次スプリントへ移行

2. **新スプリント準備**
   - [ ] 新スプリントディレクトリ作成
   - [ ] SPRINT_CONFIG.md作成（期間・目標設定）
   - [ ] バックログから作業項目選定

### 月〜木曜日: スプリント実行
1. **日次確認**
   - 進捗記録（implementation.mdの更新）
   - 課題・ブロッカーの特定
   - 必要に応じた計画調整

2. **実装記録**
   - 技術的判断の理由記録
   - 課題と解決策の文書化
   - 学習・発見事項の記録

### 木曜日: スプリント終了・振り返り
1. **完了確認**
   - [ ] 目標達成度評価
   - [ ] 成果物品質チェック
   - [ ] ドキュメント更新完了

2. **レトロスペクティブ**
   - [ ] KPT形式での振り返り実施
   - [ ] retrospective.md作成
   - [ ] 改善アクション特定

## スプリント番号付けルール

### 番号体系
- **sprint_XXX**: 3桁ゼロパディング（sprint_001, sprint_002, sprint_003...）
- **連続番号**: 欠番なしで順次増加
- **開始番号**: sprint_001から開始

### 現在の状況
- **最新スプリント**: sprint_003（2025-08-09〜2025-08-15）
- **次回スプリント**: sprint_004（2025-08-16〜2025-08-22）

## ファイルテンプレート

### SPRINT_CONFIG.md テンプレート
```markdown
# Sprint XXX 設定

## スプリント基本情報
- **開始日**: YYYY-MM-DD（金曜日）
- **終了日**: YYYY-MM-DD（木曜日）
- **期間**: 1週間
- **スプリント名**: [機能名・テーマ名]

## 目標
- メイン目標
- サブ目標

## スコープ
### 含まれる作業
### 除外する作業

## 成功基準
## リスク管理
```

### implementation.md テンプレート
```markdown
# [機能名] 実装記録

## 実装概要
## アーキテクチャ分析
## データモデル設計
## 実装計画
## 実装ガイドライン
## 進捗記録
## 技術的課題と解決方法
## 参考情報
```

### retrospective.md テンプレート
```markdown
# Sprint XXX レトロスペクティブ

## 実施日
YYYY-MM-DD

## KPT分析
### Keep（良かったこと・継続すべきこと）
### Problem（問題・課題）  
### Try（次回試すこと・改善案）

## メトリクス
### 定量指標
### 定性評価

## アクションアイテム
### 次スプリント適用項目
### 中長期改善項目

## 学習・発見事項
```

## 品質管理

### スプリント開始時チェックリスト
- [ ] 前スプリントのレトロスペクティブ完了
- [ ] 新スプリントディレクトリ作成
- [ ] SPRINT_CONFIG.md作成・レビュー
- [ ] 実装計画の妥当性確認

### スプリント実行中チェックリスト
- [ ] 日次進捗更新（implementation.md）
- [ ] 技術的判断の記録
- [ ] 課題・ブロッカーの早期特定
- [ ] 必要に応じた計画調整

### スプリント終了時チェックリスト
- [ ] 目標達成度評価
- [ ] 成果物品質確認
- [ ] レトロスペクティブ実施
- [ ] retrospective.md作成
- [ ] 次スプリント準備

## メトリクス・KPI

### 定量指標
- **目標達成率**: 設定目標に対する達成度（%）
- **実装完了率**: 予定タスクの完了率（%）
- **ドキュメント更新率**: 実装に伴う文書更新率（%）

### 定性指標
- **学習効果**: 新しい知識・スキルの習得度
- **問題解決力**: 技術的課題への対応力
- **プロセス改善**: 開発プロセスの最適化度

## アーカイブ・履歴管理

### 完了スプリントの管理
- **アーカイブ保持**: すべての完了スプリントを保持
- **参照価値**: 過去の判断記録を将来の参考資料として活用
- **学習リソース**: 新規メンバーの学習教材として利用

### 検索・参照
- **タグ活用**: #sprint #implementation #retrospective
- **Foamリンク**: 関連スプリント間の相互参照
- **インデックス**: 主要トピック別のスプリント一覧

## 継続的改善

### 四半期レビュー
- **スプリント運用の評価**: 3か月ごとの運用方針見直し
- **メトリクス分析**: KPI傾向の分析と改善策検討
- **プロセス最適化**: より効率的な運用方法の検討

### 年次改善
- **運用ルール見直し**: 年1回の大幅な運用改善
- **テンプレート更新**: 使用実績に基づくテンプレート改良
- **ツール見直し**: より良いツール・手法の検討
