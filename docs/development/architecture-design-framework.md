# アーキテクチャ設計フレームワーク

## プロジェクト概要

新機能開発時のアーキテクチャパターン選択ガイドラインを提供するフレームワークドキュメントです。

## アーキテクチャパターン詳細

### 1. ドメインモデルパターン

**適用条件**:
- 中核の業務領域
- 金銭処理、分析、監査記録以外

**特徴**:
- ビジネスロジックをドメインオブジェクトにカプセル化
- 複雑なビジネスルールを適切に表現
- オブジェクト指向設計の活用

**Odyssageでの適用例**:
- キャラクター作成・管理
- シナリオ進行管理
- 選択肢・分岐ロジック

### 2. イベント履歴式ドメインモデル

**適用条件**:
- 中核の業務領域
- 金銭処理、分析、監査記録

**特徴**:
- すべての変更をイベントとして記録
- 監査証跡の完全性
- 時系列データの分析可能性

**Odyssageでの適用例**:
- プレイ履歴記録
- ユーザー行動分析
- セッション進捗追跡

### 3. アクティブレコード

**適用条件**:
- 補完または一般との連係
- データ構造が複雑

**特徴**:
- データとその操作を一体化
- シンプルなCRUD操作
- 開発効率重視

**Odyssageでの適用例**:
- ユーザー管理
- フォーラム投稿
- テンプレート管理

### 4. トランザクションスクリプト

**適用条件**:
- 補完または一般との連係
- データ構造がシンプル

**特徴**:
- 手続き型のシンプルな処理
- 1つのトランザクションで完結
- 最小限の複雑さ

**Odyssageでの適用例**:
- 通知機能
- データバックアップ
- シンプルな検索機能

## レイヤード構成とテスト戦略

### 3層アーキテクチャ + 逆ピラミッド形テスト

**適用**: トランザクションスクリプト + 単一永続化モデル

**構成**:
- プレゼンテーション層
- ビジネス層
- データアクセス層

**テスト戦略**:
- E2Eテスト重視
- 統合テスト中心
- 単体テストは最小限

### 4層アーキテクチャ + ダイヤモンド形テスト

**適用**: アクティブレコード + 複数永続化モデル

**構成**:
- プレゼンテーション層
- アプリケーション層
- ドメイン層
- インフラストラクチャ層

**テスト戦略**:
- 統合テストが中心
- E2Eと単体テスト両方重要
- バランス重視

### ポートとアダプター + ピラミッド形テスト

**適用**: ドメインモデル/イベント履歴式

**構成**:
- アプリケーションコア（ドメイン）
- ポート（インターフェース）
- アダプター（実装）

**テスト戦略**:
- 単体テスト重視
- ドメインロジックの詳細テスト
- 統合テストは必要最小限

## 実装ガイドライン

### 設計決定プロセス

新機能開発時は以下の順序で検討してください：

1. **業務領域の分類**
   - 中核・一般・補完のどれに該当するか
   - 既存システムとの関係性

2. **データ複雑度の評価**
   - エンティティ間の関係数
   - ビジネスルールの複雑さ
   - 永続化要件

3. **品質要件の確認**
   - 監査証跡の必要性
   - パフォーマンス要件
   - 拡張性要件

4. **アーキテクチャパターンの選択**
   - フローチャートに従った決定
   - 設計判断の記録

### 実装時の注意点

- **段階的適用**: 既存システムとの整合性を保ちながら段階的に導入
- **技術スタックの制約**: TypeScript + Hono.js + React の制約内で実現
- **チーム習熟度**: 複雑なパターンは習得コストを考慮
- **メンテナンス性**: 長期的な保守性を重視
