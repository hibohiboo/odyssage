## 📅 基本情報

**作成日**: 2025-08-16

## 🎯 MVP定義・核心価値

### MVPの核心価値
**「TRPGシナリオを1人で気軽に体験できる基本的なプレイ環境の提供」**

```markdown
## 核心体験フロー
1. **セッション発見**: 利用可能なTRPGセッションを見つける
2. **セッション参加**: 興味のあるセッションに簡単に参加する
3. **基本プレイ**: シーン→選択→進行の基本的なTRPG体験
4. **完了**: プレイ完了とシンプルな記録保存

## 価値提供の優先順位
1. **没入感**: 物語世界への没入を最優先
2. **シンプル性**: 複雑な機能より直感的な操作
3. **完了性**: 中途半端な高機能より確実な基本機能
```

### GM1-vs-Player1モデル（MVP制約）

```typescript
interface MVPSessionModel {
  participants: {
    gm: 1; // ゲームマスター1名（システム）
    player: 1; // プレイヤー1名（ユーザー）
    // MVP範囲外: multiple_players: "複数プレイヤー管理";
  };
  
  session_complexity: {
    basic_flow: "シンプルなシーン進行";
    simple_choices: "明確な選択肢システム";
    // MVP範囲外: complex_mechanics: "複雑なルール・計算";
    // MVP範囲外: player_interaction: "プレイヤー間やり取り";
  };
}
```

## ✅ MVP必須機能（絶対実装）

### 1. セッション探索・選択

```markdown
## 必須機能
- ✅ セッション一覧表示
- ✅ セッション基本情報表示（タイトル・概要・状態）
- ✅ セッション詳細確認
- ✅ セッション参加機能

## 必須品質
- セッション情報の正確な表示
- 参加可能性の明確な表示
- エラー時の適切なフィードバック
```

### 2. 基本プレイ体験

```markdown
## 必須機能
- ✅ シーン表示（背景画像・説明文）
- ✅ 選択肢表示・選択
- ✅ 次シーンへの遷移
- ✅ 自動保存・状態復旧

## 必須品質
- 没入感を損なわないUI
- 意味のある選択体験の提供
- 確実な状態保存・復旧
```

### 3. 基本エラーハンドリング

```markdown
## 必須対応
- ✅ ネットワークエラー処理
- ✅ データ読み込みエラー処理
- ✅ セッション状態変更への対応
- ✅ 基本的な復旧手段提供

## 必須品質
- ユーザーにとって理解しやすいエラーメッセージ
- 明確な復旧手段の提示
- 可能な限りの自動復旧
```

## ❌ MVP範囲外機能（実装禁止）

### 1. 高度な検索・フィルタリング

```markdown
## 除外理由
BDDレビューでの学習：「シナリオ名によるフィルタリングはMVPでは不要」

## 除外機能
- ❌ 詳細検索機能
- ❌ 高度なフィルタリング
- ❌ タグベース検索
- ❌ お気に入り・ブックマーク

## 代替手段
- シンプルな一覧表示
- 基本的なカテゴリ表示（あれば）
```

### 2. 詳細な進行管理・時間表示

```markdown
## 除外理由
BDDレビューでの学習：「時間制限があるわけでもないのに、時間表示は没入感の低下と、無駄な焦りを生む」

## 除外機能
- ❌ 詳細な進行状況インジケーター
- ❌ プレイ時間表示
- ❌ チャプター・シーン数表示
- ❌ 統計・分析機能

## 代替手段
- 自動保存（バックグラウンド）
- 基本的な完了表示
```

### 3. 参加者管理機能

```markdown
## 除外理由
BDDレビューでの学習：「参加者数 | 最大参加者数 はMVPには不要」（GM1-vs-Player1モデル）

## 除外機能
- ❌ 参加者数表示
- ❌ 最大参加者数管理
- ❌ 参加者待ち・管理
- ❌ プレイヤー間コミュニケーション

## 代替手段
- 1対1のシンプルなセッション
- 即座の参加・プレイ開始
```

### 4. 高度なアクセシビリティ

```markdown
## 除外理由
BDDレビューでの学習：「MVPではキーボード操作のFeatureは外しましょう」

## 除外機能（Phase2以降で実装）
- ❌ キーボード操作対応
- ❌ スクリーンリーダー完全対応
- ❌ 高度な色覚対応
- ❌ 音声読み上げ機能

## MVP対応
- 基本的なマウス・タッチ操作
- 十分なコントラスト・読みやすさ
- 明確なタッチターゲット
```

### 5. 再プレイ・詳細履歴機能

```markdown
## 除外理由
BDDレビューでの学習：「終了したセッションは基本的には再プレイ不可としたい」

## 除外機能
- ❌ 再プレイ機能
- ❌ 詳細な選択履歴表示
- ❌ プレイ比較・分析
- ❌ 選択最適化提案

## MVP対応
- セッション完了の記録（基本）
- 新規セッションでの新しい体験
```

## 🚫 過剰品質防止ガイドライン

### 判断基準：「MVPに必須か？」

```markdown
## 機能追加時の必須チェック
1. **核心価値への貢献**: この機能は核心体験に必要か？
2. **ユーザー要求**: 実際のユーザーが要求している機能か？
3. **複雑性コスト**: 実装・保守コストに見合う価値があるか？
4. **代替手段**: より簡単な方法で同じ価値を提供できないか？

## "NO"なら実装しない
- "あると便利"は実装しない
- "将来必要になるかも"は実装しない  
- "技術的に面白い"は実装しない
- "競合他社にある"は実装しない
```

### 設計・UI/UX判断基準

```markdown
## 没入感 vs 機能性
**没入感を優先**: 機能追加が物語体験を阻害する場合は除外

例：
- ✅ シンプルな背景とテキスト表示
- ❌ 複雑なプログレスバー・統計表示

## シンプル性 vs 完全性
**シンプル性を優先**: 80%のユースケースをカバーする簡単な実装

例：
- ✅ 3-4個の明確な選択肢
- ❌ 10個以上の詳細な選択肢

## 確実性 vs 高機能
**確実性を優先**: 確実に動く基本機能 > 不安定な高機能

例：
- ✅ 基本的な自動保存
- ❌ リアルタイム同期・バックアップ
```

## 📊 品質基準・受入れ基準

### 機能品質基準

```markdown
## 基本動作（必須）
- ✅ 主要フローが途切れることなく完了できる
- ✅ データの整合性が保たれる
- ✅ エラー時に適切な復旧が可能

## ユーザー体験（必須）
- ✅ 初回利用者が説明なしで基本操作可能
- ✅ プレイ中に没入感が維持される
- ✅ 完了時に達成感・満足感が得られる

## パフォーマンス（必須）
- ✅ 3G環境で2秒以内の初期表示
- ✅ 基本的な操作応答性の確保
- ✅ エラー復旧が30秒以内
```

### 実装品質基準

```markdown
## コード品質
- ✅ TypeScript型安全性の確保
- ✅ 基本的なテストカバレッジ
- ✅ BDD Featureとの整合性

## セキュリティ
- ✅ 基本的なXSS・CSRF対策
- ✅ 適切な認証・認可
- ✅ ユーザーデータの適切な保護

## 保守性
- ✅ 明確なコード構造・命名
- ✅ 適切なコメント・ドキュメント
- ✅ 将来拡張を考慮した設計
```

## 🛡️ 過剰品質チェックリスト

### 実装前チェック

```markdown
## 機能追加前の必須確認
- [ ] この機能はMVP核心価値に直接貢献するか？
- [ ] この機能なしではMVPが成立しないか？
- [ ] より簡単な代替実装はないか？
- [ ] この機能は没入感を損なわないか？

## 設計変更前の必須確認
- [ ] この変更はBDDレビューの学習に基づいているか？
- [ ] この変更はユーザー価値を向上させるか？
- [ ] この変更は実装・保守コストに見合うか？
- [ ] この変更は他の機能に悪影響を与えないか？
```

### 実装中チェック

```markdown
## 開発中の定期確認
- [ ] 実装が当初設計の範囲内に収まっているか？
- [ ] 新しい依存関係・複雑性を追加していないか？
- [ ] BDD Featureで定義された受入れ基準を満たしているか？
- [ ] パフォーマンス基準を維持できているか？

## コードレビュー時の確認
- [ ] 過度に複雑なロジックになっていないか？
- [ ] 不要な機能・オプションが含まれていないか？
- [ ] エラーハンドリングが適切に実装されているか？
- [ ] 将来の拡張性を適度に考慮しているか？
```
