# Odyssage ドキュメント管理方針

## 基本理念

### ナレッジファースト
- **すべての設計判断を文書化**: 口頭での決定は必ず文書として記録
- **透明性の確保**: チーム内外からアクセス可能な形での情報公開
- **継続性の重視**: メンバー変更にも耐えうる知識の蓄積

### 実用性重視
- **3クリック原則**: 必要な情報に3クリック以内でアクセス可能
- **リビングドキュメント**: 実装と連動して自動更新される文書の活用
- **検索性**: Foam + VS Codeによる高速な情報検索

## ドキュメント体系

### 階層構造
```
docs/
├── 00-index.md                    # 全体インデックス（Foamハブ）
├── 01-getting-started/            # 新規参加者向け
├── 02-architecture/               # システム設計
├── 03-development/                # 開発プロセス
├── 04-deployment/                 # 運用・デプロイ
└── 05-archive/                    # 過去の記録
```

### ドキュメント分類

#### **Level 1: Core Documentation**
プロジェクトの中核となる必須ドキュメント
- `docs/03-development/process.md` (開発プロセス)
- `docs/02-architecture/database-design.md` (DB設計)
- `docs/01-getting-started/README.md` (プロジェクト概要)

#### **Level 2: Reference Documentation** 
実装者向けの詳細リファレンス
- API仕様書
- テスト戦略
- デプロイメント手順

#### **Level 3: Historical Documentation**
過去の判断記録・実装証跡
- スプリント実装記録
- 設計変更履歴
- 技術選定理由

## 作成・更新ルール

### 新規ドキュメント作成
1. **適切なディレクトリ配置**: 階層構造に従った配置
2. **命名規則遵守**: ケバブケース（`database-design.md`）
3. **テンプレート活用**: 後述のテンプレートを使用
4. **インデックス更新**: 作成時に親ディレクトリのREADME.md更新

### 更新・保守
- **リアルタイム更新**: 実装変更時の同期更新
- **リンク保守**: 月1回のリンク切れチェック
- **情報鮮度管理**: 四半期での古い情報レビュー

### バージョン管理
- **Git管理**: すべてのドキュメントをGitで管理
- **変更履歴**: コミットメッセージでの変更理由明記
- **ブランチ戦略**: 大幅変更時のfeatureブランチ活用

## Foam活用方針

### リンク戦略
- **WikiリンクFormat**: `[[ファイル名]]` 形式での相互参照
- **双方向リンク**: 関連ドキュメント間の相互リンク
- **コンテキストリンク**: 文脈に応じた自然なリンク配置

### タグシステム
```markdown
#architecture    # アーキテクチャ関連
#development     # 開発プロセス関連  
#deployment      # デプロイ・運用関連
#getting-started # 入門・概要関連
#archive         # 過去の記録
#decision        # 設計判断記録
#implementation  # 実装記録
```

### グラフビュー活用
- **知識マップ**: プロジェクト全体の知識構造可視化
- **関連探索**: 類似トピックの発見
- **孤立検出**: リンクされていない文書の特定

## 公開・共有方針

### 内部共有
- **Foam + VS Code**: 開発チーム内での日常的な知識管理
- **Git Repository**: バージョン管理された正式な記録

### 外部公開
- **GitHub Pages**: 設計判断・技術選定の透明性確保
- **静的サイト**: Astroによる読みやすい形での情報公開

### アクセス制御
- **パブリック情報**: 技術的な設計判断、学習内容
- **プライベート情報**: 個人情報、セキュリティ関連、商用機密

## 品質管理

### 文書品質基準
1. **正確性**: 実装との整合性
2. **完全性**: 必要な情報の網羅
3. **明確性**: 理解しやすい表現
4. **最新性**: 情報の鮮度維持

### レビュープロセス
- **ピアレビュー**: 重要文書の相互チェック
- **定期監査**: 四半期での情報鮮度確認
- **使用性評価**: 新規メンバーによる分かりやすさ評価

### メトリクス
- **アクセス効率**: 必要情報への到達時間
- **リンク密度**: ドキュメント間の相互参照度
- **更新頻度**: 情報の鮮度維持状況

## ツール・環境

### 必須ツール
- **VS Code**: メインエディタ
- **Foam Extension**: 知識管理機能
- **Git**: バージョン管理
- **Markdown**: 文書記述形式

### 推奨設定
```json
// VS Code settings.json
{
  "foam.openDailyNote.directory": "docs/03-development/daily-notes",
  "foam.workspaceType": "foam",
  "markdown.preview.breaks": true
}
```
