## 🔍 パフォーマンス分析

### 改善点

1. **データベースセットアップ最適化**
   - 現在: 各テストでfull cleanup + insert
   - 提案: トランザクションベースのクリーンアップ
   - 期待効果: 20-30%の実行時間短縮

2. **テストデータ共有化**
   - 現在: beforeEach で毎回データ再作成
   - 提案: beforeAll でベースデータ作成、beforeEach で必要最小限のみ
   - 期待効果: 15-25%の実行時間短縮

3. **並列実行最適化**
   - 現在: 順次実行
   - 提案: 依存関係のないテストの並列実行
   - 期待効果: 30-40%の実行時間短縮

### 遅いテストの特定

**100ms超過テスト**: 
- ストック一覧取得テスト (104ms)
  - 理由: 2回のAPI呼び出し + データベース操作
  - 対策: API呼び出し回数の最小化

**80ms超過テスト**:
- 重複防止テスト (91ms)
- 削除後冪等性テスト (92ms)
  - 理由: 複数回のAPI呼び出し
  - 対策: テストロジックの最適化

## 💡 最適化提案

### 短期的改善 (実装コスト: 低)

1. **beforeEach最適化**
```typescript
// 現在の実装
beforeEach(async () => {
  await execSql(getConnectionString(), 'delete from odyssage.scenario_stock');
  await execSql(getConnectionString(), 'delete from odyssage.scenarios');
  await execSql(getConnectionString(), 'INSERT INTO odyssage.scenarios...');
});

// 最適化後の提案
beforeEach(async () => {
  // scenario_stockのみクリーンアップ（scenariosは保持）
  await execSql(getConnectionString(), 'delete from odyssage.scenario_stock');
});
```

2. **API呼び出し回数削減**
```typescript
// 現在: 2回のAPI呼び出し
const listRes = await api.getStockedScenarios(testUserId);
const stocks = await listRes.json();

// 最適化後: 結果の再利用
const stocks = await api.getJsonResponse(listRes);
```
